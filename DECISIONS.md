# Decisions

Short notes on choices made while building, so you can change them knowingly.

## Learning design
- **Added a “Write it back” step** (step 3) right after the first animation. Retrieval practice, writing from memory, is
  the most reliable way to make things stick, and your original flow only had writing at the very end.
- **Writing steps gate “Next” by default** (Write it back, Recap). Turn this off in Settings if it gets in the way.
- **Narration plays with each animation frame** and auto-play waits for the voice. Research on multimedia learning
  (Mayer’s modality and redundancy principles) favours spoken words + visuals over visuals + lots of on-screen text,
  so on-screen text is kept to one caption line.
- **Labels sit on the things they label** (pointer tags on nodes), not in legends.
- **Spaced review** at 1, 3 and 7 days after finishing a topic: rewrite your saved explanation from memory, then a
  quick recall question. The Review page also offers **mixed practice** across finished topics.
- **Problems are original**, built on the same patterns as well-known interview problems, and the matching real
  LeetCode problems are linked as extra practice. Several problems include a large test so an O(n²) solution
  visibly times out, which teaches why the better complexity matters.

## Visual design
- Three themes chosen from mockups: **Mix** (default: chalkboard + solid blocks), **Chalk**, **Blocks**. Same role
  colours in all: head blue, current yellow, new pink, second pointer purple, done green, danger red.
- Fonts: Caveat (handwriting), Atkinson Hyperlegible (body text, designed for legibility), Bricolage Grotesque
  (blocks), JetBrains Mono (code). All bundled, no external font requests.
- Diagrams **auto-zoom** to their content so they stay large on laptops and readable on phones.

## Technical
- **Hash routing** (`/#/learn/...`) so it works on any static host with zero config.
- **Python runs in a Web Worker** with an 8-second limit. Pyodide is loaded from jsDelivr
  (`pyodide@314.0.8`); override with `VITE_PYODIDE_URL` to self-host.
- **One test harness** (`src/python/harness.py`) is used both in the browser and by `npm run verify`, which runs in
  Node with the same Pyodide version. So “verified” means verified in the same runtime you use.
- **Content is TypeScript, not JSON**, because animations are generated by small functions (e.g. a trace computed
  from the actual algorithm). Topic files are pure (no React), so they can be tested in Node.
- **Storage**: the whole progress document is one JSON row per user in Supabase (simple, and merges are done
  client-side). localStorage is always kept as a local copy.
- The teaching hash function in the Hash Maps topic is “sum of letter codes mod buckets”. It is deliberately simple
  so you can compute it by hand; the topic points out that real hashes mix in letter positions.
- Read-aloud uses the browser’s built-in voices, so quality depends on your browser and OS (Chrome/Edge/Safari
  have the best voices).
- **Test sizes in linked-list and tree problems are capped (about 2,000 nodes).** Freeing a very long chain of Python
  objects recurses deeply and overflows Pyodide’s JavaScript stack. If learner code ever crashes Python this way, the
  app restarts the interpreter automatically and says what happened.
- **Several expected values were cross-checked independently** (e.g. by brute force with NumPy) instead of trusting the
  reference solution alone.
- **The app waits for saved progress to load before rendering**, so opening a problem directly never shows starter
  code over your saved work.
- Supabase sync is implemented against the documented supabase-js v2 API but could not be tested against a live
  project from the build environment.
